1. 概要

捻じれた魔術は、収容プラットフォームに拘束したアノマリーの近くで瞑想することで進む成長システムです。 瞑想している入植者と、範囲内にいるアノマリーの種族との間に「繋がり」（connection、0〜100）が蓄積され、 25 / 50 / 75 / 100 の閾値を越えるたびに段階（tier）が解放されます。

段階に紐付いた AbilityDef と HediffDef はその場で入植者に付与されます。 逆に、対象を失ったり瞑想を放置したりすると繋がりは減衰し、閾値を割り込むと解放済みの能力も取り上げられます。 魔法の使用そのものにコストはなく、能力ごとのクールダウンだけで制御されています。

アノマリーを収容→ 傍らで瞑想→ 繋がり +5 / 時間→ 閾値で段階解放→ 能力 / hediff を獲得

繋がりの保存先は入植者側の VoidAwake_CompVoidMagic で、 Patches/Patch_VoidMagic.xml がすべての人型 ThingDef（他 mod の追加種族を含む）に注入します。 入植者ごとの繋がり一覧は、インスペクタの「捻じれた魔術」タブで確認できます。

瞑想スポットは必須ではありません。JobDriver_Meditate を使うジョブであれば、 バニラの瞑想でも娯楽としての瞑想でも同じように繋がりが伸びます。 収容室の中で瞑想させるだけで成立します。
システムは Anomaly DLC が有効なときだけ動作します（VoidAwake_VoidMagicUtility.Active）。 また、既定テンプレートの段階には能力が設定されていないため、 現時点で実際に魔術が使えるのはサイトスティーラーとの繋がりだけです。 それ以外のアノマリーでは、繋がりと段階名の表示までが動きます。

2. 繋がりの対象

繋がりは個体ではなく種（ThingDef）に対して結ばれます。 収容していた個体が死んでも、同じ種を別の個体で収容し直せば繋がりは維持されます。

対象になる条件

VoidAwake_VoidMagicUtility.IsLinkableEntityDef が判定します。 次の 3 つをすべて満たす ThingDef が対象です。

race が非 nullPawn である
race.Humanlike が false人型を除外する
CompProperties_HoldingPlatformTarget を持つ収容プラットフォームに拘束できる

この条件により、Anomaly DLC の収容可能エンティティは Def を 1 行も書かずに全種が対象になります。 他 mod が追加した収容可能エンティティも自動的に含まれます。

人型を除外しているのは、シャンブラーやクリープジョイナーが Human ThingDef のまま収容されるためです。 除外しないとタブに「人間との繋がり」という行が出てしまいます。

数値の決まり方

対象種ごとの数値と段階は VoidAwake_VoidMagicDef が持ちます。 VoidAwake_VoidMagicUtility.DefFor(entityDef) が次の順で解決します。

優先Def条件
1entityDef を指定した VoidAwake_VoidMagicDefその種に一致する Def があるとき
2VoidAwake_VoidMagicDefault専用 Def が無いすべての種（既定テンプレート）

entityDef ごとの対応表と対象 ThingDef の一覧は、初回参照時に一度だけ構築されてキャッシュされます （EnsureCaches）。一覧はラベル順にソートされます。

3. 瞑想と獲得

瞑想とみなされるジョブ

VoidAwake_VoidMagicUtility.IsMeditationJob が真になるジョブ中は、繋がりが伸びます。

  • 専用ジョブ VoidAwake_VoidMeditate（捻じれた瞑想）
  • driverClass が JobDriver_Meditate を継承するすべてのジョブ。バニラの Meditate、娯楽としての瞑想、Royalty のサイフォーカス瞑想、それらを継承した他 mod のジョブが該当します

加えて IsMeditatingNow が、マップ上にいること・死亡や気絶をしていないこと・ pather.MovingNow が false であることを確認します。移動中は加算されません。

獲得量

加算は 250 tick ごと（VoidAwake_CompVoidMagic.CompTickRare 内で経過 tick が UpdateIntervalTicks = 250 に達したとき）に、経過分をまとめて処理します。 

獲得量 = connectionPerHourMeditating / 2500 × 経過tick × (1 / 範囲内の対象数) × gainMultiplier
connectionPerHourMeditating既定 5.0。瞑想 1 時間（2500 tick）あたりの獲得量
範囲内の対象数複数体が範囲にいると頭数で割られる。合計獲得量は変わらない
gainMultiplier足元の瞑想スポットの倍率。スポットに乗っていなければ 1.0
上限maxConnection（既定 100）で頭打ち

つまり既定値では、対象 1 体に絞って 20 時間瞑想すると 0 から 100 に到達します。 2 体を同時に範囲へ入れると、それぞれ 2.5 / 時間ずつ伸びます。

探索半径

瞑想している入植者の足元に VoidAwake_CompMeditationAnchor を持つ建物があれば、その radius と gainMultiplier を使います。無ければ DefaultMeditationRadius = 9.9 セル、倍率 1.0 です。 半径内の Building_HoldingPlatform を走査し、拘束されている対象を集めます。

4. 減衰と維持

減衰は加算と同じ 250 tick の更新で処理されます。加算を先に行ってから減衰を見るため、 瞑想している間に繋がりが減ることはありません。経過 tick から日数へ換算するので、更新間隔に結果は依存しません。

3 つの状態。判定は VoidAwake_CompVoidMagic.DecayPerDayFor
状態条件減衰 / 日タブ表示
喪失対象種がどのプレイヤーマップにも収容されていないdecayPerDayLost
既定 6.0		喪失 -6.0/日
放置収容中だが、最後に繋がりが伸びてから idleGraceDays（3 日）が経過decayPerDayIdle
既定 1.0		放置 -1.0/日
維持収容中かつ猶予日数の内側0収容中・維持

既定値では、対象を失ってから約 4.2 日で段階を 1 つ失い（100 → 75）、 約 16.7 日で繋がりが 0 になります。放置減衰だけなら 1 段階落ちるまで 25 日かかります。

収容の判定は全プレイヤーマップを横断します（ContainedEntityDefsNow）。 別のマップの拠点で収容していても「喪失」にはなりません。 走査結果は 600 tick キャッシュされます。

繋がりが 0 まで落ちた行はリストから削除され、タブから消えます。 ただし、その種が現在収容されていれば「まだ繋がりのない対象」として行自体は表示され続けます。

5. 段階（tier）

各 VoidAwake_VoidMagicDef は tiers のリストを持ちます。 1 段階は「ラベル・閾値・能力リスト・hediff」の 4 項目で、能力と hediff は省略できます。 リストは読み込み時に threshold の昇順へ自動ソートされます。

VoidAwake_VoidMagicTier のフィールド
label段階名。翻訳対象（[MustTranslate]）。省略時は閾値がそのまま表示される
threshold解放に必要な繋がり。既定 25
abilities解放時に付与する AbilityDef のリスト
hediff解放時に付与する HediffDef（1 つ）

解放と剥奪

現在の段階は TierIndexFor(connection) が返します。閾値を満たす最上位の段階の添字で、 どれにも届かなければ -1 です。この値が変化したときだけ ApplyTierContent が走り、 全段階を走査して次の処理を行います。

繋がりが変化→ TierIndexFor で段階を算出→ 解放済み: 能力 / hediff を付与+ 未解放: 能力 / hediff を剥奪→ メッセージ通知

付与は pawn.abilities.GainAbility と pawn.health.AddHediff、 剥奪は RemoveAbility と RemoveHediff です。 いずれも重複チェックを挟むため、同じ能力を二重に得ることはありません。

段階が上下すると、対象がプレイヤー操作の入植者である場合にメッセージが出ます （上昇は PositiveEvent、下降は NegativeEvent）。 セーブのロード中は通知されません。

既定テンプレートの段階

専用 Def が無いすべてのアノマリーに、VoidAwake_VoidMagicDefault の 4 段階が使われます。 現状は能力・hediff とも空で、段階名の表示だけが機能します。

段階閾値中身
微かな共鳴25なし
共振50なし
深き共鳴75なし
同化100なし
中身の無い段階はタブのツールチップで「能力は未実装」と明示されます（VoidAwake_VoidMagicTier.HasContent）。

7. UI と操作

「捻じれた魔術」タブ

VoidAwake_ITab_Pawn_VoidMagic（540 × 420）。 inspectorTabs はバニラの BasePawn 側で定義されているため、パッチはそこへ 1 行追加しています。 動物やメカにも付きますが、表示条件で絞られるため出てきません。

表示条件（すべて満たしたときのみ）
Anomaly DLC有効であること
対象プレイヤー操作の入植者であること
compVoidAwake_CompVoidMagic を持つこと

行は「繋がりを持つアノマリー」と「現在収容中のアノマリー」の合併で、繋がりの降順に並びます。 まだ 0 の収容アノマリーも行として出るため、これから伸ばせる対象が一覧で分かります。 繋がりが 1 件も無く、収容もしていない場合は、瞑想スポットの設置を促す案内文だけが表示されます。

1 行の構成
アイコン対象アノマリーの ThingIcon（40 px）
ゲージ紫の横棒。各段階の閾値位置に縦線マーカーを描き、到達済みは黄、未到達は灰。中央に「現在値 / 上限」を小さく表示
段階名右上。解放済みなら黄色で段階名、未解放なら灰色で「未接続」
状態段階名の下。維持（緑）／喪失・放置（赤、減衰量付き）／瞑想したことがない（灰）
ツールチップ全段階の一覧（解放済みは +、未解放は -、中身が無ければ「能力は未実装」）と、獲得量・減衰量の数値

瞑想スポット

  • 右クリックのフロートメニューに「捻じれた瞑想を行う」。実行できない場合は理由を添えたグレーの項目として出ます
  • Inspect 欄に半径内の収容アノマリー名を列挙します。いなければ「範囲内に収容されたアノマリーがない。」
  • 建物を選択すると探索半径のリングを描画します（VoidAwake_Building_VoidMeditationSpot）。Royalty の瞑想スポットは thingClass が異なるためリングは出ません

メッセージ

アノマリーごとの魔術を追加する

entityDef を指定した VoidAwake_VoidMagicDef を 1 つ書けば、既定テンプレートを上書きできます。 段階に abilities や hediff を書けば、そのまま付与・剥奪の対象になります。 

<VoidAwake.VoidAwake_VoidMagicDef>
	<defName>VoidAwake_VoidMagic_Revenant</defName>
	<entityDef>Revenant</entityDef>
	<connectionPerHourMeditating>3</connectionPerHourMeditating>
	<tiers>
		<li>
			<label>faint resonance</label>
			<threshold>40</threshold>
			<!-- ここに hediff / abilities を書くと解放時に付与される -->
		</li>
	</tiers>
</VoidAwake.VoidAwake_VoidMagicDef>
ConfigErrors により、maxConnection が 0 以下、または tiers が空の Def は起動時にエラーを出します。

デバッグアクション

Dev Mode のデバッグアクション（カテゴリ「VoidAwake」、マップ上でのみ有効）。対象は選択中の入植者です。

VoidMagic: add connection +25選んだアノマリーとの繋がりを 25 加算する
VoidMagic: fill connection選んだアノマリーとの繋がりを上限まで埋める
VoidMagic: clear connections繋がりをすべて削除する
VoidMagic: dump links全入植者の繋がり・段階・減衰量をログへ出力する

アノマリーの選択リストは、現在収容中のものが * 付きで先頭に並びます。
