1. 概要

本機能は Anomaly の保持台（Holding Platform）収容に対する VoidAwake 側のルール変更と拡張枠です。 大きく二つの柱があります。

  • 完全収容 — 足場の収容強度がエンティティの必要収容強度以上なら、脱走抽選も連鎖脱走も絶対に発生しない。
  • 特殊脱走イベント — 脱走が起きたとき、そのアノマリーに紐づくイベント Def を順に発火する。各 Def にはアノマリー別の脱走レターが設定されている。ワーカー本体は現状ほぼ空実装。
バニラとの差分
項目バニラVoidAwake
収容強度が足りているとき 脱走間隔（MTB）が延びるだけ（最大約 8 倍）。ゼロにはならない 脱走間隔が Never。抽選そのものが起きない
収容強度が足りないとき 従来どおり MTB 抽選 従来どおり（本パッチは介入しない）
脱走発生時 台から排出・敵ターゲット設定・同室連鎖・汎用脅威レター バニラ処理のあと、アノマリー別イベントを発火（レター含む）。VoidAwake レターがある initiator 脱走ではバニラレターを抑止
イベントワーカーはほぼ空実装ですが、各イベント Def には letterLabel / letterText が設定されており、 脱走時にアノマリー別レターが送られます。個別演出はワーカーの DoEscapeEvent を実装すれば足せます。

2. 完全収容（脱走阻止）

判定式

足場がエンティティを「安全に収容している」とみなす条件は、バニラの Thing.SafelyContains と同じです。

CompEntityHolder.ContainmentStrength >= entity.GetStatValue(MinimumContainmentStrength)

保持台の検査文が赤字（収容強度不足）でなければ脱走しない、という対応になります。 保持スポット（HoldingSpot）は containmentFactor 0.7 が掛かるため、同じ部屋でも保持台より不利です。

差し込み点

バニラの脱走抽選は CompHoldingPlatformTarget.CaptivityTick が 2500 tick ごとに行い、 ContainmentUtility.InitiateEscapeMtbDays が負なら抽選しません。 同室の連鎖脱走も同じ関数が <= 0 なら参加しません。 InitiateEscapeMtbDays は冒頭で CanParticipateInEscape を呼び、false なら即 -1 を返します。

したがって VoidAwake は ContainmentUtility.CanParticipateInEscape の Postfix 一箇所だけを変更します。 収容強度が足りていれば __result = false にし、ITab 用の内訳文字列に VoidAwake_FactorSafelyContained（日本語: 収容強度が十分）を追記します。

結果プレイヤーに見えるもの
完全収容中 エンティティタブの脱走間隔が Never。ツールチップ内訳に「収容強度が十分: x0%」
強度不足 従来どおり日数表示の脱走間隔
Dev ギズモや ForceEscapeRoom による強制脱走は、この阻止パッチを経由しません。 収容強度が足りていても強制脱走できます（イベント確認用）。

3. 脱走時の処理フロー

CaptivityTick
2500 tick→ InitiateEscapeMtbDays→ CanParticipateInEscape
（強度足りれば false）→ MTB 抽選→ Escape(initiator)
Prefix: 足場 / Map / Cell 退避→ EjectContents → 敵設定 → 連鎖 → バニラレター（抑止可）→ Postfix: イベント順に発火（レター送信）

Escape は冒頭で EjectContents を呼ぶため、Postfix 時点では HeldPlatform が null になります。 そのため Prefix で足場・Map・座標を VoidAwake_EscapeContext に退避してからイベントへ渡します。

連鎖脱走では各ポーンが個別に Escape(initiator: false) を呼びます。 各ポーンごとに自分のまとめ Def のイベントが発火します。

4. Def の 2 層構造

Def は「イベント 1 件」と「アノマリー 1 体分のまとめ」に分かれています。 同じイベントを複数アノマリーで使い回したり、1 体に複数イベントを組み合わせたりできます。

Def役割主なフィールド
VoidAwake_ContainmentEscapeDef アノマリー 1 体分の脱走設定 entityDef / mutantDef / events
VoidAwake_EscapeEventDef 脱走時に起こる 1 イベント（再利用可） workerClass / chance（既定 1） / onlyWhenInitiator / letterLabel / letterText / letterDef / letterOnlyWhenInitiator

解決優先度

ContainmentEscapeUtility.ContainmentEscapeDefFor が次の順でまとめ Def を選びます。

  1. entityDef と mutantDef の両方が一致
  2. mutantDef のみ指定された Def が一致
  3. entityDef のみ指定された Def が一致
  4. どちらも未指定の Def（VoidAwake_ContainmentEscape_Default）

4 のフォールバックがあるため、DLC や他 Mod でアノマリーが増えても専用 Def を書くまでは既定イベントが走ります。

イベント固有のパラメータが必要になったら、VoidAwake_EscapeEventDef を継承した Def を作り、 XML の Class= で指定します。

6. イベントワーカー契約

型役割
VoidAwake_EscapeEventWorker 基底。仮想メソッド DoEscapeEvent(VoidAwake_EscapeContext ctx)。既定は空
VoidAwake_EscapeContext 脱走時の状況。足場は既に排出済みなので、位置は Prefix 退避値
VoidAwake_EscapeContext のフィールド
フィールド内容
pawn脱走したエンティティ
platform脱走直前に収容していた保持台
map / cell脱走地点
initiator自力で脱走を開始したなら true。連鎖側は false
イベント発火時のフィルタ
フィールド挙動
chance 1 未満なら Rand.Chance で抽選。既定 1（常に発火）
onlyWhenInitiator true なら連鎖脱走側（initiator = false）では発火しない

Notify_Escaped はまとめ Def の events を順に回し、フィルタ通過後にワーカーを呼びます。 例外はイベント単位の try/catch で握るため、1 つ落ちても後続イベントとバニラの脱走処理は完走します。

現状、すべてのアノマリー用ワーカー（EscapeEventWorkers_Vanilla.cs）は空実装です。

7. 拡張手順

新しいアノマリーに専用脱走イベントを付ける手順は次の 3 ステップです。

  1. VoidAwake_EscapeEventWorker を継承したクラスを追加し、DoEscapeEvent を実装する （当面は Events/EscapeEventWorkers_Vanilla.cs に並べ、育ったら個別ファイルへ切り出す）。
  2. Defs/Containment/EscapeEventDefs.xml にイベント Def を 1 件足し、workerClass にそのクラスを指定する。
  3. Defs/Containment/ContainmentEscapeDefs.xml にまとめ Def を 1 件足し、events でそのイベントを参照する。 人型ミュータントなら mutantDef、通常エンティティなら entityDef。

イベント Def 例

<VoidAwake.VoidAwake_EscapeEventDef>
  <defName>VoidAwake_EscapeEvent_Revenant</defName>
  <workerClass>VoidAwake.VoidAwake_EscapeEventWorker_Revenant</workerClass>
</VoidAwake.VoidAwake_EscapeEventDef>

まとめ Def 例

<VoidAwake.VoidAwake_ContainmentEscapeDef>
  <defName>VoidAwake_ContainmentEscape_Revenant</defName>
  <entityDef>Revenant</entityDef>
  <events><li>VoidAwake_EscapeEvent_Revenant</li></events>
</VoidAwake.VoidAwake_ContainmentEscapeDef>

8. デバッグ

完全収容中は自然脱走が起きないため、イベント確認には強制脱走を使います。

手段内容
保持台ギズモ DEV: Escape (room) その保持台がある部屋の収容エンティティを全て脱走させる。収容強度は無視
VoidAwake → Containment: force escape in room マップツール。クリックしたセルの部屋に対して同じ処理
VoidAwake → Containment: dump escape events 収容可能なアノマリーごとに解決される Def とイベントをログ出力。(DEFAULT) 付きが専用イベント未定義
バニラ DEV: Escape / Timed escape 選択中の 1 体のみ

部屋の判定範囲はバニラの連鎖脱走と同じ「部屋内および隣接」（Room.ContainedAndAdjacentThings）。 ForceEscapeRoom は最初の 1 体だけ initiator: true で呼ぶため、レターは 1 通に収まります。
